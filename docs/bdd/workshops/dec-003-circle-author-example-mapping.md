# DEC-003：社團與作者 Example Mapping

狀態：已確認

## 目標

將原本過於籠統的問題「`社團 (作者)` 是否永遠成立？」拆成可逐項決定的規則。所有建議都要求保留原始 bracket 文字，避免 parser 拆錯後無法追查。

## 語料概況

從目前 13,566 筆收藏中，以只讀方式找到 13,162 筆可用的 leading bracket 候選：

| 形狀 | 筆數 | 備註 |
|---|---:|---|
| 可由最外層尾端括號拆成 `社團 (作者區段)` | 10,137 | 主流格式 |
| 沒有作者括號的單一 bracket | 3,012 | 同人誌／CG 多為社團；商業誌多為作者 |
| 作者區段含候選分隔符 | 446 | 是主流格式的子集合 |
| 作者區段含巢狀括號 | 6 | 包含別名、表情或名稱本身的括號 |
| 括號不完整或括號不在尾端 | 13 | 不適合自動拆解 |

候選作者分隔符分布：

| 分隔符 | 筆數 | 可靠度觀察 |
|---|---:|---|
| `、` | 250 | 高機率表示多人作者 |
| `,` | 163 | 高機率表示多人作者，但部分檔名本身已破損 |
| `&` | 25 | 可能是多人，也可能是名稱的一部分 |
| `＆` | 5 | 同上 |
| `×` | 3 | 有 `3×3` 這類不是多人作者的案例 |
| `／` | 1 | 樣本不足 |

## 規則 A：標準的單一作者格式

範例：

```text
[23.4ド (イチリ)]
[C.R's NEST (しーあーる)]
```

### 建議

若 leading bracket 以平衡圓括號結尾：

- 最外層尾端括號以前保存為社團原始值。
- 最外層尾端括號內保存為作者區段原始值。
- 不丟棄完整 bracket 原始值。

### 決策 A

**決策：接受。**

## 規則 B：使用頓號或逗號的多人作者

範例：

```text
[NoFuture (すみすず、端音乱希)]
[サークルくれじっと (ベンジャミン, あきかん, 無一文)]
```

### 建議

- 作者區段原始值完整保存。
- `、` 與 `,` 可產生多位作者候選清單。
- 每個拆出的作者保留其來源位置。
- 若 bracket 或圓括號不平衡，不執行多人拆分。

### 決策 B

**決策：作者使用清單，同時保留作者區段原始字串。**

## 規則 C：`&`、`＆`、`×`、`／` 等模糊分隔符

範例：

```text
[apricot (黑男 & 杏二)]
[QP：flapper (さくら小春＆小原トメ太)]
[multiplication (3×3)]
```

### 建議

- 不依這些符號自動拆成多人作者。
- 保留整個作者區段原始值。
- 外部 metadata 或人工修正可以提供結構化作者清單。

### 決策 C

**決策：只自動拆 `、` 與 `,`，其他符號不拆。**

## 規則 D：只有單一 bracket、沒有作者括號

範例：

```text
[無糖紅茶]
[K.Y.HIRO]
```

語料中的現況分布：

- 同人誌：1,787 筆目前當成只有社團。
- CG：750 筆目前當成只有社團。
- 成年コミック：310 筆目前當成只有作者。
- 少量資料後來透過人工或其他流程同時補上了社團與作者，代表檔名本身不足以證明唯一角色。

### 建議

- 上層分類為同人誌或 CG 時，單一 bracket 先作為社團解析值。
- 上層分類為商業誌時，單一 bracket 先作為作者區段解析值。
- 兩者都保留原始 bracket 與來源為「檔名解析」。
- 更高優先的外部 metadata 或人工修正可以補充或取代角色判斷。

### 決策 D

**決策：接受依上層分類決定單一 bracket 的角色。**

## 規則 E：作者區段含巢狀括號

範例：

```text
[macdoll (士嬢マコ(・c_・ ))]
[おかりな_ (ぢょんたいらん(野々原幹))]
```

### 建議

- 只切最外層尾端括號，取得社團與作者區段。
- 作者區段內的巢狀括號視為作者名稱的一部分。
- 不遞迴猜測巢狀括號是別名、另一位作者或其他 metadata。

### 決策 E

**決策：接受拆最外層，但不再拆作者內部巢狀括號。**

## 規則 F：括號不完整或不在尾端

抽象形狀：

```text
[社團 (作者]
[社團 (作者))]
[社團 (作者) 其他文字]
```

### 建議

- 不自動填入社團或作者結構化欄位。
- 完整 bracket 保存為「其他資訊」。
- 記錄括號不平衡或結構不明，並嘗試以外部 metadata 補足社團與作者。
- 外部結果達到採用條件時，不需要送人工確認。
- 外部搜尋失敗或結果不夠可靠時，才標記 `needs_review`。

### 決策 F

**決策：filename parser 不猜；先嘗試外部搜尋補足，外部結果仍不可靠時才送人工確認。**
