# 第一輪待確認決策

以下問題來自現有程式碼中的模糊、不一致或高風險行為。請先確認這些問題，再把接受的答案轉成 Rust v2 的 `@proposed` scenarios。

## Parser 與資料所有權

1. **已決定（DEC-001）**：除已辨識的分類前綴外，任意開頭 `(內容)` 視為場次。
2. **已決定（DEC-002）**：尾端 `(內容)` 缺少原作證據時歸入「其他資訊」，不填入原作。
3. **已決定（DEC-003）**：拆最外層社團與作者；作者用清單並保留原文；只自動拆 `、` 與 `,`；單一 bracket 依上層分類決定角色；巢狀作者不再拆；破損結構先嘗試外部補足，仍無可靠結果才送人工確認。
4. **已決定（DEC-004）**：保留「成年コミック／官能小説／一般コミック」子分類，全部歸入上層分類「商業誌」。
5. **已決定（DEC-005）**：同時保存檔名原始值與 canonical 正式名稱；例如保留 `ポケモン`，並將 `ポケットモンスター` 保存為正式名稱。
6. **已決定（DEC-006）**：自動掃描只解析新收藏；parser 更新不自動重跑既有收藏。
7. **已決定（DEC-007）**：手動修改 > 外部 metadata > 檔名解析 > 推斷結果；逐欄位來源記錄由 proposed BDD 要求保留可追溯性。

## 掃描與檔案生命週期

8. **已決定（DEC-008）**：舊路徑消失且出現同名候選時，舊收藏從有效 Library 移除，但保留 tombstone、metadata 與 tags 供人工裁決。
9. **已決定（DEC-009）**：同名不足以自動判定搬移；舊收藏 tombstone 與所有候選都保留，必須由人工裁決。
10. **已決定（DEC-010）**：批次搬移只能從下載區移到已設定的歸檔區，後端也必須強制限制。
11. **已決定（DEC-011）**：批次搬移可以部分成功；成功與失敗項目分開處理並逐筆回報。
12. **已決定（DEC-012）**：刪除時可選軟刪除或永久刪除；軟刪除送到作業系統資源回收桶，永久刪除不經資源回收桶。

## Metadata 建議與合併

13. **已決定（DEC-013）**：所有欄位統一依 metadata 來源優先序處理；原作沒有特殊覆寫權，覆寫手動值必須由使用者明確裁決。
14. **已決定（DEC-014）**：Confidence 採來源可靠度、識別碼匹配、字串相似度與規則確定度的綜合分數，並保留分項與理由。
15. **已決定（DEC-015）**：總信心度至少 0.95、具有可靠識別碼完全匹配且沒有手動衝突時才可自動套用；0.75 至 0.95 顯示待確認建議，低於 0.75 只保留搜尋紀錄。只有部分欄位可靠時可以部分成功。
16. **已決定（DEC-016）**：Canonical 優先採已確認的官方名稱，不固定日文優先；沒有官方資料時才依語言與使用次數推薦，並保存使用者拒絕合併的排除規則。

## UI、設定與安全

17. **已決定（DEC-017）**：最近開啟紀錄只保存在目前瀏覽器，不需要跨瀏覽器或裝置同步。
18. **已決定（DEC-018）**：依錯誤種類與時間安排縮圖重試；暫時性錯誤延遲重試並退避，永久性錯誤等待檔案變更或手動重試。
19. **已決定（DEC-019）**：服務只綁定 localhost loopback，不允許透過設定暴露到區域網路。
20. **已決定（DEC-020）**：Rust v2 保留「系統預設開啟」與「指定閱讀器閱讀」兩種動作。
21. **已決定（DEC-021）**：設定變更後自動排程重建既有縮圖，也提供手動重建功能。
22. **已決定（DEC-022）**：手動清空不建立最高優先的空白值；移除手動值後，較低優先來源仍可重新成為有效值。
